## 关键修复（3 个）

### 修复 1：patchelf 移除 gralloc.so 的 bionic libhardware.so.2
- **问题**：gralloc.so NEEDED bionic libhardware.so.2 → glibc ld.so 加载 bionic libc.so → TLS 冲突 → 崩
- **解决**：patchelf --remove-needed libhardware.so.2 gralloc.so，改成 libhybris 的 glibc 包装版
- **命令**：
  ```bash
  patchelf --remove-needed libhardware.so.2 gralloc/.libs/libgralloc.so.1.0.0
  patchelf --add-needed libhardware.so.2 gralloc/.libs/libgralloc.so.1.0.0  # 加回 glibc 版
  ```

### 修复 2：HYBRIS_TLS_PATCH=1（patch Mali blob 的 TLS 偏移量）
- **问题**：Mali blob（libGLES_mali.so）内联访问 bionic TLS 槽 → 和 glibc TLS 槽撞车 → segfault
- **解决**：libhybris commit f47e718（2025-02-17，TheKit）引入 TLS access patcher
- **命令**：
  ```bash
  HYBRIS_TLS_PATCH=1  # 或 HYBRIS_TLS_PATCH=libGLES_mali.so（只 patch mali blob）
  ```
- **源代码**：hybris/common/tls_patcher.c + tls_patcher_aarch64.c

### 修复 3：libhybris 的 glibc libhardware.so.2（包装 Android libhardware.so）
- **问题**：gralloc.so 直接链接 Android bionic libhardware.so.2 → 拉入 bionic libc.so → TLS 冲突
- **解决**：用 libhybris 编译的 glibc libhardware.so.2（HYBRIS_IMPLEMENT_FUNCTION 包装 Android libhardware.so）
- **位置**：libhybris/hybris/hardware/.libs/libhardware.so.2.0.0（73KB，glibc 版）

## libhybris 编译（完整流程）

### 源代码
- **libhybris**：https://github.com/libhybris/libhybris（commit f47e718，2025-02-17）
- **Android headers**：https://github.com/Halium/android-headers（分支 halium-7.1）

### 编译命令（电脑交叉编译 arm64）
```bash
# 1. Clone
git clone https://github.com/libhybris/libhybris.git
cd libhybris
git checkout f47e718  # TLS patcher commit

git clone -b halium-7.1 https://github.com/Halium/android-headers.git

# 2. 依赖（电脑）
sudo apt install -y autoconf automake libtool pkg-config m4
sudo apt install -y gcc-aarch64-linux-gnu g++-aarch64-linux-gnu

# 3. gralloc.c 补丁（halium-7.1 headers 缺声明）
# hybris/gralloc/gralloc.c，加在 #include <hardware/gralloc.h> 后
# extern native_handle_t* native_handle_clone(const native_handle_t* handle);

# 4. autogen + configure
cd hybris
NOCONFIGURE=1 ./autogen.sh
./configure --host=aarch64-linux-gnu \
    --with-android-headers=/path/to/android-headers \
    --enable-arch=arm64 --enable-trace --disable-glvnd --prefix=/usr

# 5. 编译（跳过 tests）
make -j12 -C common      # libhybris-common.so（含 TLS patcher）
make -j12 -C egl         # libEGL.so
make -j12 -C glesv2      # libGLESv2.so
make -j12 -C glesv1      # libGLESv1_CM.so
make -j12 -C gralloc     # libgralloc.so
make -j12 -C libsync     # libsync.so
make -j12 -C hardware    # libhardware.so.2（glibc 版，包装 Android libhardware.so）
make -j12 -C platforms   # libhybris-platformcommon.so
make -j12 -C egl/platforms  # eglplatform_null.so + eglplatform_fbdev.so + eglplatform_hwcomposer.so

# 6. patchelf 修复 gralloc.so
patchelf --remove-needed libhardware.so.2 gralloc/.libs/libgralloc.so.1.0.0
patchelf --add-needed libhardware.so.2 gralloc/.libs/libgralloc.so.1.0.0
```

## 核心经验（5 条）

1. **Mesa 内部 ABI 不稳定**（Panfork 23.0.0 vs 系统 25.0.7 版本冲突），所有组件必须来自同一版本同一编译
2. **libhybris 需要 TLS patcher**（HYBRIS_TLS_PATCH=1，patch Mali blob 的内联 TLS 访问）
3. **glibc ld.so 不能加载 bionic libc.so**（TLS 冲突），必须用 patchelf 移除 NEEDED 依赖
4. **libhybris 的 glibc 包装库**（libhardware.so.2 包装 Android libhardware.so，不直接加载 bionic）
5. **设备节点全在**（/dev/mali0 + /dev/ion + /dev/binder + /dev/graphics/fb0），TWRP 里都能访问
