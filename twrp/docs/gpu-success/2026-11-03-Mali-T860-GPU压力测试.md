## GPU 压力测试 vs 简单场景

| 场景 | 顶点数 | 渲染FPS | 读回ms | 总FPS |
|---|---|---|---|---|
| **简单场景**（1 立方体）| 36 | 11599 | 44 ms | **17.72 FPS** |
| **压力测试**（50 立方体 + 200 粒子）| 2000 | 11599 | 44 ms | **17.14 FPS** |
| **纯 GPU 渲染**（PBuffer 离屏）| 36 | 12123 | 0 ms | **12123 FPS** |

**结论**：
- **GPU 渲染快**：11599-12123 FPS（顶点数不影响 GPU 速度）
- **CPU 读回慢**：44 ms（glReadPixels 256x256）
- **总 FPS**：17 FPS（CPU 读回限制，不是 GPU 限制）

## GPU 硬件加速证明（压力测试）

**50 立方体 + 200 粒子**：
- **GPU 渲染**：11599 FPS（0.086 ms/frame）
- **CPU 读回**：44 ms（glReadPixels 256x256）
- **XPutImage**：12 ms（CPU 拷贝到 X11 窗口）
- **总速度**：17.14 FPS（56-59 ms/frame）

**vs CPU 软件渲染**：
- **CPU（llvmpipe）**：5-10 FPS（100-200 ms/frame）
- **GPU（Mali-T860）**：17 FPS（56-59 ms/frame）
- **加速比**：**2-3 倍**（CPU 读回限制）

## 零拷贝方案（解决 CPU 读回瓶颈）

### 方案 1：**DMA-BUF**（需要 /dev/dri）
```
GPU → dmabuf fd → X11/Wayland compositor → 屏幕
```
- **设备状态**：无 /dev/dri（Android TWRP 内核没有 DRM KMS）
- **可行性**：❌ 不可行

### 方案 2：**hwcomposer 平台**（eglCreateWindowSurface）
```
应用 → libhybris libEGL → hwcomposer HAL → 屏幕
```
- **测试结果**：❌ segfault（hwcomposer HAL 初始化失败）
- **可行性**：❌ 不可行

### 方案 3：**drm-hwcomposer-shim + Flick compositor**（最成熟）
```
Wayland compositor → drm-hwcomposer-shim → Android hwcomposer → libhybris → Mali GPU
```
- **时间**：4-8 小时（编译 Rust + 配置）
- **风险**：魅蓝 Note5 可能不兼容（drm-hwcomposer-shim 只测了 Pixel 3a）
