## 二、Xorg 配置（fbdev + fb0）

### 2.1 xorg.conf

```
# /etc/X11/xorg.conf
Section "ServerLayout"
    Identifier "Layout0"
    Screen 0 "Screen0"
EndSection

Section "Device"
    Identifier "Device0"
    Driver "fbdev"
    Option "fbdev" "/dev/graphics/fb0"
EndSection

Section "Screen"
    Identifier "Screen0"
    Device "Device0"
    DefaultDepth 24
    SubSection "Display"
        Depth 24
        Modes "1080x1920"
    EndSubSection
EndSection
```

### 2.2 启动 Xorg

```bash
Xorg :0 -config /etc/X11/xorg.conf > /tmp/xorg.log 2>&1 &
```

**坑：fbdev 不支持 Rotate 选项**
- 加 `Option "Rotate" "CW"` → Xorg 启动但 "no screens found"
- 去掉 Rotate 即可（旋转是软件层，fbdev 驱动不支持）

### 2.3 屏幕颠倒问题

**现象**：手机屏 180 度上下颠倒，但 VNC 显示正的

**原因**：fb0 物理方向（手机屏物理朝向颠倒），Xorg 直接写 fb0 不做旋转

**解法**：
- **不改 Xorg**（fbdev 不支持 rotate）
- **VNC 客户端旋转**（vncviewer 菜单 Connection > Rotation）

## 三、远程投屏（x11vnc + SSH 隧道）

### 3.1 装 x11vnc

```bash
apt-get install -y --no-install-recommends x11vnc
```

### 3.2 启动 x11vnc（关键参数）

```bash
export DISPLAY=:0
nohup x11vnc -display :0 \
    -nopw \
    -noshm \
    -forever \
    -listen 0.0.0.0 \
    -rfbport 5900 \
    -noxdamage \
    > /tmp/x11vnc.log 2>&1 &
```

### 3.3 踩坑

**坑 1：-nopass 无效**
```
错误：x11vnc: Unrecognized option '-nopass'
正确：-nopw
```

**坑 2：shmget: Function not implemented**
```
原因：内核没 SYSV IPC 共享内存
解法：加 -noshm
```

**坑 3：X DAMAGE 失败**
```
解法：加 -noxdamage
```

### 3.4 SSH 隧道

```bash
# 电脑上起
ssh -f -N -L 5900:localhost:5900 meilan-phone1

# 验证
ss -tln | grep 5900
```

### 3.5 连 VNC

```bash
# 装 tigervnc-viewer
sudo apt install -y tigervnc-viewer

# 连
vncviewer -SecurityTypes None localhost:5900
```

## 四、Power 键开关屏

### 4.1 问题：找不到 power 键

**测试方法**：读所有 input 设备，按按键看哪个响应

```python
# read-all-events.py
import os, struct, threading, time

EVENT_SIZE = 24  # arm64 input_event

def read_device(dev_path, dev_name, results):
    fd = os.open(dev_path, os.O_RDONLY)
    while not results["stop"]:
        data = os.read(fd, EVENT_SIZE)
        if len(data) != EVENT_SIZE:
            continue
        tv_sec, tv_usec, ev_type, code, value = struct.unpack("<qqHHi", data)
        if ev_type == 0x01 and value == 1:  # EV_KEY 按下
            print(f"[+] {dev_name}: type={ev_type} code={code} value={value}")

# 监听所有 /dev/input/event*
# 结果：event3 mtk-kpd code=116 (KEY_POWER)
```

### 4.2 设备列表

| event | 名称 | 用途 |
|---|---|---|
| event0 | hall_sensor | 霍尔传感器 |
| event1 | compass | 指南针 |
| event2 | ACCDET | 耳机检测 |
| **event3** | **mtk-kpd** | **MTK 按键（power/home/back）** |
| event4 | gf-keys | 指纹键 |
| event5 | hwmdata | 硬件监控 |
| event6 | m_alsps_input | 光感 |
| event7 | mtk-tpd | 触屏 |

**power 键 = event3 mtk-kpd code=116**

### 4.3 power-key-toggle.py

```python
#!/usr/bin/env python3
import os
import struct

BL = "/sys/class/leds/lcd-backlight/brightness"
EV = "/dev/input/event3"  # mtk-kpd (power 键)
EVENT_SIZE = 24  # arm64: timeval(16) + type(2) + code(2) + value(4)

def toggle_backlight():
    with open(BL, "r") as f:
        current = int(f.read().strip())
    new = 0 if current > 0 else 255
    with open(BL, "w") as f:
        f.write(str(new))
    print(f"[+] backlight: {current} -> {new}")

def main():
    fd = os.open(EV, os.O_RDONLY)
    print(f"[*] 监听 {EV} (power 键)")
    while True:
        data = os.read(fd, EVENT_SIZE)
        if len(data) != EVENT_SIZE:
            continue
        tv_sec, tv_usec, ev_type, code, value = struct.unpack("<qqHHi", data)
        # EV_KEY (0x01) + KEY_POWER (116) + 按下 (value=1)
        if ev_type == 0x01 and code == 116 and value == 1:
            print(f"[+] Power 键按下")
            toggle_backlight()

if __name__ == "__main__":
    main()
```

### 4.4 后台运行

```bash
setsid nohup python3 /root/power-key-toggle.py \
    > /tmp/power-key.log 2>&1 < /dev/null &
```

### 4.5 实测

```
按 power 键 → 日志显示 "[+] Power 键按下"
背光切换：255 -> 0 -> 255 -> 0
```

## 十、屏幕翻转（Rotate UD，物理屏正，VNC 也正）

### 10.1 问题

- **手机物理屏**：显示翻转 180 度（上下颠倒）
- **电脑 VNC**：显示正常（不翻转）
- **原因**：手机面板安装方向 180 度（硬件物理朝向），扫描 fb0 时显示翻转

### 10.2 解法（Rotate UD）

**Xorg 加 `Option "Rotate" "UD"`**（fbdev 驱动支持）：

```
# /etc/X11/xorg.conf
Section "Device"
    Identifier "Device0"
    Driver "fbdev"
    Option "fbdev" "/dev/graphics/fb0"
    Option "Rotate" "UD"
EndSection
```

**效果**：
- **手机物理屏**：显示正（Xorg 渲染时预翻转，抵消面板翻转）
- **电脑 VNC**：显示正（x11vnc 抓 fb0 原样，fb0 内容不变）
- **性能损耗**：x11vnc 9% CPU + Xorg 3% CPU，温度 39.9°C，负载 10

### 10.3 机制（为什么 VNC 也正）

| 层 | Rotate UD 影响 | 原因 |
|---|---|---|
| X11 内容 | 不变（正）| Xorg 渲染 X11 时正常，Rotate UD 只影响写 fbdev |
| fb0 内容 | **翻转**（反）| Xorg 写 fb0 时软件翻转（Rotate UD）|
| x11vnc 抓 | 正（抓 X11）| x11vnc 用 XShmGetImage 抓 X11，不读 fb0 |
| 电脑 VNC | 正 | VNC 读 X11 内容（正）|
| 手机物理屏 | 正 | 面板反向扫描 fb0（180 度安装），fb0 翻转 + 面板翻转 = 正 |

**关键**：fbdev Rotate UD = Xorg 写 fb0 时软件翻转，只影响物理屏，不影响 X11 内容（VNC 正）。

### 10.4 踩坑

**坑 1：Rotate 值错**
- "CW"/"180" 无效
- 正确："UD"（Upside Down = 180 度翻转）

**坑 2：fb0 rotate 参数无效**
- `echo 180 > /sys/class/graphics/fb0/rotate` 无效
- rotate 是内核 fbdev 参数，不是 Xorg 旋转

**坑 3：fbturbo 驱动装不到**
- Debian trixie 没有 xserver-xorg-video-fbturbo 包
- 只能用 fbdev + Rotate UD

**坑 4：Rotate UD 不稳定（误判）**
- 我以为 Rotate UD 不稳定（"过了一会黑屏"）
- 实际：黑屏原因不明（不是 Rotate UD 的错）
- 用户要求实测稳定性，测了 3 分钟+，稳定

### 10.5 性能优化

**x11vnc 事件驱动**（去掉 -noxdamage，用 X DAMAGE 扩展）：
```bash
pkill x11vnc
nohup x11vnc -display :0 -nopw -noshm -forever -listen 0.0.0.0 -rfbport 5900 > /tmp/x11vnc.log 2>&1 &
```

**x11vnc 降轮询频率**（-wait 200，CPU 降到 5%）：

## 十一、Rotate UD 性能实测（翻转 vs 不翻转）

### 11.1 实测对比（稳态）

| 项 | 不翻转 | 翻转 Rotate UD | 差异 |
|---|---|---|---|
| lxpanel CPU | 3.1% | 4.7% | +1.6% |
| pcmanfm CPU | 2.0% | 3.3% | +1.3% |
| Xorg CPU | 0.9% | 1.4% | +0.5% |
| openbox CPU | 0.4% | 0.6% | +0.2% |

### 11.2 结论（用户验证）

- **CPU 是真的**（翻转 +2% CPU）
- **电流/温度是噪声**（不可信）
- **Rotate UD 性能开销小**（CPU +2%，可接受）

### 11.3 机制澄清

- **Rotate UD = Xorg 写 fb0 时软件翻转**
- **只影响物理屏**（fb0 内容翻转，面板反向扫描抵消）
- **不影响 VNC**（x11vnc 抓 X11，fb0 内容无关）
- **fb0-flip-daemon 废弃**（numpy 没装，失败退出）
